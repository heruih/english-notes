# 决策记录（为什么是这样）

> 目的：**防止以后有人（包括 AI、包括未来的你）重提已经否过的方案。**
> 每条写三件事：当时为什么这么选、代价是什么、什么情况下值得重新考虑。
> 不是历史文档——是**挡箭牌**。

---

## D1. 单文件 HTML，不用框架

**决策**：一个 `.html` 文件装下所有 CSS/JS，无构建、无依赖、无 CDN。

**理由**：手机离线能直接打开；换设备只要传一个文件；没有构建链就没有"构建失败"这一类问题。

**代价**：405 KB、442 个函数全在一个文件里；每次改动都要 AI 重读全文，token 成本高；多人交接必然混乱（已经发生过）。

**什么时候重议**：拆成 `src/js/*.js` + `build.py`，产物仍是单文件——**这不叫推翻 D1，叫补上它的缺口。**真正推翻 D1（改成多文件部署）需要理由：出现第二个使用者、需要热更新。

---

## D2. 不引入框架（Vue / React / Next.js）

**决策**：原生 JS + `contenteditable`。

**理由**：框架带来打包体积、构建链、版本升级、hydration 问题；这个 App 的交互核心是"编辑一段富文本 + 弹一个词卡"，原生够用。

**代价**：状态变更要手动调 `render()`；组件复用靠函数拼接。

**什么时候重议**：**基本不会。**反面教材就在旁边——Trinity 用 Next.js 做私人工具，框架包 500 KB，功能没比它多。

---

## D3. 数据只在浏览器本地（localStorage）

**决策**：没有后端、没有账号、没有数据库。主键 `english-notes-app-v1`。

**理由**：零成本、零延迟、零隐私风险；一个人用不需要服务端。

**代价**：换设备要手动搬；清浏览器数据就没了（所以有导出备份和同步码）。

**什么时候重议**：真出现"多人使用"或"跨设备实时"需求时。**目前明确不做**（见需求 D-4/5）。

---

## D4. 同步走 Gist / WebDAV + 同步码，不自建后端

**决策**：多设备同步用 GitHub Gist 或 WebDAV，再加一个 `ENSYNC1:` 的 base64 同步码做"无网络也能搬"。

**理由**：不自建服务器、不付费、不维护。

**代价**：配置麻烦（token、地址、ID）；CORS 与 Gist 超时踩过多次；token 明文存本地。

**什么时候重议**：如果同步连续三次以上失败，或者用户开始抱怨配置——那时再考虑"一键导入导出文件"替代。

---

## D5. 复习用 Leitner 分箱，不用 SM-2/FSRS

**决策**：`srs.box` 1–6，间隔 `[0,0,1,3,7,15,30]` 天，评分三档（忘了/难/记住了）。

**理由**：三个按钮能解释清楚；算法可预测、可调试；不需要"难度系数"这类黑箱参数。

**代价**：不如 FSRS 精准。

**什么时候重议**：自用 30 天后如果发现"该复习的没出现/不该出现的总出现"，再考虑。

---

## D6. AI 只补例句，绝不覆盖释义与标签

**决策**：`definition` / `phonetic` / `tags` 由用户手填；AI 生成的 `examples` 只追加、去重、不覆盖。

**理由**：用户主权——释义是他自己的理解，AI 一覆盖就变成"背 AI 的话"。

**代价**：录入比全自动慢。

**什么时候重议**：**不重议。**这是产品价值观，不是技术选择。

---

## D7. 词典页复刻欧路格式，不接词典 API

**决策**：词典页的数据由已配置的 AI 按欧路结构生成 JSON。

**理由**：有道 jsonapi 带 Origin 就 403；dictionaryapi.dev 在 `file://` 下被 CORS 拦；datamuse 无 CORS 头。**离线 + 单文件**和"直连词典 API"天然冲突。

**代价**：释义与真实词典有出入；词条质量取决于模型。

**什么时候重议**：出现愿意付费的词典 API，且能解决 CORS/离线问题。

---

## D8. 发音：有道真人音源 + 系统 TTS

**决策**：单词走有道 `dictvoice`；句子和中文走浏览器 `speechSynthesis`（女声优先，rate 0.95）。

**理由**：试过模仿豆包"小姐姐"音色，多版合成后**固定录音无法朗读任意句子**，只能回退。豆包音色是字节私有的，网页做不到。

**代价**：音色不统一（单词一个声音、句子另一个声音）。

**什么时候重议**：字节开放 TTS 公开接口，或愿意接火山引擎（要付费、要后端签名）。

## 决策的元规则

1. **推翻一条决策，必须写清三件事**：新证据是什么、代价能否接受、什么时候能回滚。
2. **"看起来更专业"不是理由**。上一个"更专业"的选择（Next.js）让 Trinity 付出了 500 KB 框架的代价。
3. **凡是改数据结构、改同步、改 AI 行为的决策，先看 `docs/数据模型.md` 的兼容铁律。**
