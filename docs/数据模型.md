# 数据模型（改字段之前必读）

> 这份文件存在的唯一理由：**防止任何一个 AI "顺手把字段改个名"，把你的数据全弄丢。**
> 规则很简单——**只能加，不能改名，不能删。**

---

## 一、存储位置

浏览器 `localStorage`。**没有后端，没有数据库，没有账号。**

主键：`english-notes-app-v1`（常量名 `LS_KEY`）——**这是全部业务数据**。

## 二、主数据结构

```js
{
  v: 1,                 // 结构版本，改结构时递增
  at: 1699999999999,    // 导出的时间戳
  device: 'dev_xxx',    // 设备标识（同步合并用）
  folders: [ … ],
  notes:   [ … ],
  words:   [ … ],
  aiLog:   [ … ],       // AI 调用记录（最多保留一定条数）
  grave:   [ … ],       // 墓碑：删除记录
  tagList: ['职场','日常'],
  meta:    { backupAt, device, sync:{…} },
  settings:{ baseUrl, apiKey, model, tone, theme, fs }
}
```

### folders

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | `f_` 前缀 |
| `name` | string | 文件夹名 |
| `createdAt` | number | 毫秒时间戳 |

### notes

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | `n_` 前缀 |
| `folderId` | string | 所属文件夹 |
| `title` | string | 大标题 |
| `content` | string | **HTML**（contenteditable 产出，不要当纯文本处理） |
| `createdAt` / `updatedAt` | number | 毫秒 |
| `sel` | object? | 可选，光标位置 `{path, off}`，用于重进时恢复光标 |

### words（核心）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | `w_` 前缀 |
| `term` | string | 单词或词组 |
| `phonetic` | string | 音标，可空 |
| `definition` | string | 释义（用户手填，AI 不许覆盖） |
| `examples` | `[{en, cn}]` | 例句对；AI 只追加去重，不改已有 |
| `tags` | string[] | 标签 |
| `notes` | `[{noteId, noteTitle}]` | 出现在哪些笔记里（引用，非拷贝内容） |
| `source` | `'demo'\|'ai'\|'dict'\|'manual'` | 来源；`demo` 是预置示例，可一键清空 |
| `createdAt` / `updatedAt` | number | 毫秒 |
| `mastered` | boolean | 旧的"已掌握"标记（兼容保留，**不要删**） |
| `srs` | object | 间隔复习状态，见下 |

### words.srs（Leitner 分箱）

```js
srs: { box: 1..6, due: 时间戳, last: 时间戳, reps: 次数, lapses: 遗忘次数 }
```

- 间隔天数 `SRS_DAYS = [0, 0, 1, 3, 7, 15, 30]`，箱位 1–6 对应"1 天后 / 3 天后 / 7 天后 / 15 天后 / 30 天后"
- 评分 `grade`：`0` 忘了（降箱 + 10 分钟后重来）、`1` 有点难（同箱，间隔 ×0.6）、`2` 记住了（升箱）
- `mastered` 与 `srs` 是**两套并存**：`mastered` 为兼容旧数据保留；新逻辑一律读 `srs`
- 缺失 `srs` 时由 `ensureSrs()` 补齐，**不要写迁移脚本去批量改**

### grave（墓碑）

```js
{ t: 'word'|'note'|'folder', id: 'w_xxx', at: 时间戳 }
```

- 删除不真删，而是记一条墓碑，同步时用它来合并"哪边删了"
- 上限 800 条，超出时丢最旧的（`slice(-800)`）
- **不要清空 grave**——清空会导致已删除的内容在下次同步时"复活"

### meta.sync

```js
{ provider:'gist', ghToken, ghGistId, url, user, pass, auto:true, lastAt, lastBy }
```

**`ghToken` / `pass` 是明文存在本地的**。任何导出、截图、日志、同步码里都不许带上它们。

## 三、兼容铁律（违反即数据丢失）

1. **字段只加不改不删。** 要改语义就加新字段（如 `srs`），老的保留。
2. **读到不认识的字段，原样保留。** 序列化时必须原样写回，不许白名单裁剪。
3. **迁移必须幂等**：跑两次结果一样；迁移前把原始数据备份到 `*-archive` key（已有先例：`qmarks-v1` → `qmarks-v1-archive`）。
4. **`v` 字段只在结构不兼容时递增**，且必须同时写迁移函数。
5. **id 前缀不能变**：`f_` / `n_` / `w_` 是同步合并的判据之一。
6. **`content` 是 HTML**，任何"文本化"处理都会破坏富文本和圈词。

## 四、改动前必答

- 这次改的是**新增字段**，还是**改了已有字段的含义**？（后者一律拒绝，除非用户明确同意）
- 老用户的数据读进来会怎样？**写一条测试用例说明。**
- 备份在哪？改完能不能一键回滚？

## 五、禁止清单

- 禁止用"清理代码"为由重命名字段
- 禁止清空 `grave`、删除 `qmarks-v1` 迁移源
- 禁止把 `ghToken` / `apiKey` / `pass` 写进导出文件、同步码、日志、截图
- 禁止在没有备份的情况下跑批量数据迁移
