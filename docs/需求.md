# 需求（一页纸）

> 写这份文件的唯一目的：**让任何一个接手的人 / AI，在加功能之前先知道"不做什么"。**
> 改这份文件 = 改产品方向，要作者本人点头。

---

## 1. 给谁用

**第一用户只有一个人：作者本人。**

- 场景：看全英视频（访谈、球赛解说、vlog、电影）时遇到陌生表达
- 动作：截图 → 记进笔记 → 圈出那个词 → 补例句 → 之后复习、跟读
- 目的：**不是背词表，是把"我真实遇到过的表达"留下来，并且能用出去**

## 2. 解决什么问题

市面上的单词 App 是**词表驱动**（今天背 List 3），他要的是**内容驱动**（今天我看到的这句话）。

现状痛点：
1. 截图散在相册，生词散在备忘录，**找不到**
2. 记了不复习，**记了就忘**
3. 复习时只有中文意思，**不知道它当时怎么用**

所以本产品的中心不是"词库"，是**自己的笔记**——词从笔记里长出来。

## 3. 做什么（V1 范围，已实现）

一条闭环：**记笔记 → 圈词 → AI 补例句 → 复习 → 跟读**

1. 文件夹 + 富文本笔记（备忘录式自动保存、光标记忆）
2. 选中单词「empower」→ 单词卡（音标/释义/标签手动填）
3. AI 按词义补例句（只追加、去重，不覆盖手动内容）
4. 标签聚合 + 生词本三态（全部/未掌握/已掌握）
5. 艾宾浩斯 SRS 闪卡复习 + 模糊搜索
6. 有道真人音源朗读 + 跟读录音回放
7. 情景口语四步练习（选场景 → 口译 → 打分 → 跟读）
8. 跨设备同步（自带凭据，非账号体系）

## 4. 不做什么（**这一节最重要**）

| 不做 | 原因 |
|---|---|
| 社交 / 排行榜 / 打卡 / 好友 | 一个人用的工具，社交是负担 |
| 账号体系、注册登录 | 数据在本地，没有账号概念 |
| 内置词库、离线词典包 | AI 按需生成就够，词典包会让体积爆炸 |
| 多设备实时协作 | 同步只做"备份 + 合并"，不是多人协作 |
| 电脑版 / 浏览器插件版 | 只做手机，只做手机，只做手机 |
| 付费、订阅、商业化 | 自用满 30 天之前，一个字都不谈 |
| 学习计划、打卡提醒、推送 | 先证明自己会用，再谈督促 |
| 引入框架 / CDN / 外部依赖 | 单文件、离线可用是底线 |

## 5. 硬约束（不许破）

- **数据只在浏览器本地**，localStorage key 固定为 `english-notes-app-v1`
- **绝不动已有数据**；新功能一律用独立的 key，不复用旧 key
- **交付物是单文件**，但源码要分模块（`src/js/*.js` + `build.py`），`dist/` 由构建生成
- 中文界面、全黑主题、手机优先（iPhone Safari 为准）
- 离线可用：断网时除了 AI 例句和朗读，其余全部要能用

## 6. 怎么算"成功"（30 天验收）

不是"功能齐全"，是这三条：

1. **连续 30 天**，每天至少打开并记一条
2. 30 天后能回答：**哪些功能我一次都没用过**（→ 砍掉）
3. 30 天后能回答：**哪一步最烦**（→ 优化那一步，不是加新功能）

## 7. 加功能前的三个问题

1. **它替我决定了什么？**（说不出来就砍）
2. **它属于第 3 节那八条里的哪一条？**（不属于就砍）
3. **怎么验证它有用？**（说不出验证方法就先别做）

## 附：现状 ≠ 需求

当前代码里有 442 个函数、同步逻辑占了很大比重——**这代表历史，不代表方向**。
凡与本文件第 4 节冲突的功能，一律视为"待冻结/待移除"，而不是"要维护的部分"。
